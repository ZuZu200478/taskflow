# TaskFlow－智慧任務管理器規格書

## 一、製作動機

在處理課業、報告、研究、工作與生活事項時，常常會同時累積多項待辦任務。一般待辦清單主要記錄任務名稱與完成狀態，但當任務增加時，使用者仍不容易判斷哪些事情應該優先處理。

因此，本專案製作一個名為 **TaskFlow** 的任務管理 Web App。除了基本的新增、編輯、刪除與狀態管理，也記錄任務的群組、重要性、緊急度、難度與截止時間，並透過日曆、時間軸及任務優先矩陣，協助使用者安排處理順序。

## 二、目標使用者與使用情境

主要使用者為需要同時管理多項事情的大學生、研究生，以及有個人工作與生活規劃需求的使用者。

| 類別 | 使用情境 |
| --- | --- |
| 📚 課業 | 追蹤作業、考試準備與課堂報告 |
| 🔬 研究 | 安排閱讀論文、實驗與資料整理 |
| 💼 工作 | 管理專案事項與進度 |
| 🎹 社團 | 規劃活動、會議與企劃繳交 |
| 🏠 生活 | 記錄採買、預約與個人待辦事項 |

## 三、專案目標與範圍

1. 提供任務新增、查看、編輯與刪除功能。
2. 透過四種狀態管理任務進度。
3. 提供搜尋、篩選與排序功能。
4. 以日曆、時間軸與優先矩陣呈現任務。
5. 使用瀏覽器本機儲存，重新整理後仍保留紀錄。
6. 支援電腦與手機操作。
7. 所有程式碼整合為單一 `index.html`，透過 GitHub Pages 發布。

本版本不提供帳號登入、雲端同步、多人協作或通知提醒。

## 四、任務資料規格

| 欄位 | 格式與範圍 | 說明 |
| --- | --- | --- |
| 任務識別碼 | 系統自動產生 | 用於辨識、更新與刪除任務 |
| 任務名稱 | 必填，最多 100 字元 | 不接受只有空白的名稱 |
| 任務描述 | 選填，最多 2,000 字元 | 記錄細節、步驟或補充資訊 |
| 所屬群組 | 五種固定群組 | 課業、研究、工作、社團、生活 |
| 截止日期與時間 | 必填 | 用於排序、日曆、時間軸與矩陣計算 |
| 重要性 | 1～5 級 | 數值越高代表越重要 |
| 緊急度 | 1～5 級 | 使用者主觀判斷的急迫程度 |
| 難度 | 1～3 級 | 簡單、普通、困難 |
| 任務狀態 | 四種固定狀態 | 待辦、進行中、已完成、已結案 |
| 建立時間 | 系統自動記錄 | 記錄任務建立時間 |
| 完成時間 | 系統自動記錄 | 用於今日完成率計算 |

新增任務時，狀態預設為「待辦」，群組預設為「課業」，重要性與緊急度預設為 3 級，難度預設為 1 級，截止時間預設為隔天相同時間。使用者可修改所有可填寫欄位。

截止時間可設定在過去，以便記錄已逾期事項。日期與時間依目前裝置的本地時間顯示。

## 五、任務管理功能

### 5.1 新增任務

使用者點選「＋新增任務」，開啟表單，填寫資料後按下「儲存任務」。必填資料未填寫時，系統提示使用者並阻止儲存。

儲存成功後，任務加入列表及對應的日曆日期、時間軸與優先矩陣，任務統計立即更新，資料寫入 LocalStorage。

### 5.2 編輯任務

使用者可從任務卡片或詳細資訊視窗開啟編輯表單。表單應帶入原有資料，允許修改名稱、描述、群組、截止時間、重要性、緊急度、難度與狀態。儲存後，各檢視與統計同步更新。

### 5.3 刪除任務

點選「刪除」後，系統顯示確認視窗及任務名稱。

- 點選「取消」：保留任務。
- 點選「確認刪除」：移除任務並更新儲存資料。
- 刪除後無法復原。

### 5.4 狀態管理

一般操作流程為：**待辦 → 進行中 → 已完成 → 已結案**。

| 狀態 | 定義 | 卡片主要操作 |
| --- | --- | --- |
| 待辦 | 尚未開始 | 開始任務 |
| 進行中 | 正在處理 | 完成任務 |
| 已完成 | 工作已完成，仍保留於主要檢視 | 結案 |
| 已結案 | 已確認結束，保留於歷史紀錄 | 編輯、刪除 |

已結案任務從列表、日曆、時間軸與優先矩陣隱藏，集中顯示於「已結案」頁面。使用者也可透過編輯表單直接調整狀態，例如將已結案任務改回待辦，使其重新出現在主要檢視中。

### 5.5 任務屬性與群組

- **重要性（1～5 級）**：代表任務的重要程度，用於矩陣的水平位置，也可作為篩選與排序條件。
- **緊急度（1～5 級）**：代表使用者主觀判斷的急迫程度，可作為篩選與排序條件，不直接決定矩陣的垂直位置。
- **難度（1～3 級）**：★ 簡單、★★ 普通、★★★ 困難。
- **群組**：課業、研究、工作、社團、生活，使用不同顏色輔助辨識。

## 六、Dashboard 任務總覽

電腦版將 Dashboard 放在主要內容左側，顯示待辦、進行中、已完成、已結案數量，以及今日完成率與進度條。

統計以全部已儲存任務計算，不受搜尋與篩選條件影響。新增、編輯、刪除或改變狀態後，統計立即更新。

### 今日完成率

統計範圍為「截止日期是今天」或「完成日期是今天」的任務。同一項任務即使同時符合兩個條件，也只計算一次。

**今日完成率＝統計範圍中已完成或已結案的任務數 ÷ 統計範圍內任務總數 × 100%**

結果四捨五入為整數百分比。沒有符合條件的任務時顯示 0%。

首次將任務設定為已完成或已結案時，系統記錄完成時間。若改回待辦或進行中，則清除完成時間；之後再次完成時重新記錄。

## 七、任務列表與卡片

任務列表使用卡片顯示尚未結案的任務。每張卡片顯示名稱、描述、群組、目前狀態、重要性、緊急度、難度星數、截止時間，以及狀態操作、編輯與刪除按鈕。

已超過截止時間且狀態仍為待辦或進行中的任務，顯示「已逾期」及醒目文字。已完成與已結案任務不顯示逾期警示。

## 八、日曆功能

日曆以月份呈現任務的截止日期，提供「上個月」、「下個月」、「本月」及日期選取功能。

### 顯示與互動規則

1. 每週由星期日開始排列。
2. 使用六列、七欄的日期格，包含前後月份的補足日期。
3. 今日以暖橘色標示，選取日期使用明顯邊框。
4. 電腦版日期格最多顯示兩項任務名稱，超過時顯示額外數量。
5. 手機版主要顯示任務數量，避免文字擠壓。
6. 點選日期後，下方顯示當天任務卡片，依截止時間由早到晚排列。
7. 當天沒有符合條件的任務時，顯示提示。

日曆套用上方搜尋與篩選條件。即使沒有任務，也仍顯示完整日曆。已結案任務不顯示於日曆中。

## 九、時間軸功能

時間軸依截止日期分組，並依時間由早到晚排列。當天顯示「今天」，隔天顯示「明天」，其他日期顯示完整日期。

每筆資料顯示截止時間及任務卡片，使用者可直接開始、完成、結案、編輯與刪除任務。時間軸固定按截止時間排列，並套用搜尋與篩選條件。

## 十、任務優先矩陣

優先矩陣以十字型四象限呈現尚未結案的任務，包含已完成但尚未結案的任務。

### 10.1 X 軸：重要性

由左至右，重要性由低到高。1～2 級位於左側，3 級位於中線，4～5 級位於右側。

### 10.2 Y 軸：時間壓力

由上至下，時間由充裕到緊迫。時間壓力根據截止時間與目前時間計算：

**時間壓力＝1－剩餘時間 ÷ 7 天**

結果限制在 0～1 之間。

| 剩餘時間 | 時間壓力與位置 |
| --- | --- |
| 7 天以上 | 時間壓力為 0，位於上方 |
| 3.5 天 | 時間壓力為 0.5，位於垂直方向中線 |
| 越接近截止時間 | 時間壓力越高，位置越往下 |
| 已到期或逾期 | 時間壓力為 1，位於底部 |

矩陣在網頁開啟期間每分鐘更新一次；任務資料變更時也立即更新。

### 10.3 四象限定義

| 時間壓力 | 重要性低 | 重要性高 |
| --- | --- | --- |
| 時間充裕 | 可規劃 | 重要但可安排 |
| 時間緊迫 | 低優先／快速處理 | 優先處理 |

右下角表示任務重要性高且截止時間接近，可作為優先處理的參考。

### 10.4 矩陣互動

- 任務點使用群組顏色與編號。
- 點選任務點或下方任務名稱，可開啟詳細資訊。
- 詳細資訊包含名稱、描述、群組、截止時間、重要性、緊急度、難度與狀態。
- 可從詳細資訊視窗開啟編輯表單。
- 相近位置的點略微錯開，以減少重疊；判斷仍以實際屬性數值為準。

## 十一、搜尋、篩選與排序

搜尋與篩選放在主要工作區最上方。

### 搜尋

以關鍵字搜尋任務名稱與描述，輸入後即時更新結果。

### 篩選

支援任務狀態、群組、重要性、緊急度與難度。多項條件同時使用時，任務必須符合所有條件才會顯示。

### 排序

任務列表與已結案紀錄支援：

- 截止時間：近到遠。
- 重要性：高到低。
- 緊急度：高到低。
- 難度：高到低。

屬性數值相同時，再依截止時間由近到遠排列。時間軸與日曆當日清單固定使用截止時間排序。

### 重設與檢視切換

點選「重設」後，清除搜尋與篩選條件，恢復截止時間排序。切換主要檢視時清除狀態篩選，其他搜尋與篩選條件保留。

## 十二、介面與視覺設計

### 電腦版配置

1. **頂部導覽**：品牌名稱與檢視切換。
2. **工作區最上方**：搜尋、分類篩選、排序與重設。
3. **左側**：任務總覽與今日完成率。
4. **右側**：頁面標題、新增任務按鈕與主要檢視內容。

導覽選單為：**任務列表｜日曆｜時間軸｜優先矩陣｜已結案**。

### 配色與樣式

- 奶油白作為背景與主要表面。
- 暖橘色作為主要按鈕、選取與今日標示。
- 深棕色文字維持閱讀對比。
- 柔和邊框、圓角與適量陰影區隔資訊。
- 群組以不同色彩輔助辨識。
- 逾期任務使用醒目的紅色文字。

### 手機版配置

- 導覽與篩選依螢幕寬度調整排列。
- 左側統計改為上方多欄排列。
- 任務卡片改為單欄。
- 日曆日期格以任務數量為主。
- 表單與視窗維持在螢幕範圍內。

## 十三、操作流程

1. 開啟 TaskFlow，查看任務總覽。
2. 點選「＋新增任務」，填寫任務資料。
3. 儲存後，任務加入對應檢視。
4. 利用搜尋、篩選與排序縮小查看範圍。
5. 透過列表、日曆、時間軸或矩陣安排處理順序。
6. 開始工作時，將任務標記為進行中。
7. 完成工作後，標記為已完成。
8. 確認事情完全結束後結案。
9. 需要查詢歷史時，進入已結案紀錄。

整體流程為：**新增任務 → 設定屬性 → 查看與安排 → 開始任務 → 完成任務 → 結案**。

## 十四、資料儲存與錯誤處理

### 儲存方式

使用 LocalStorage 保存任務資料，不需帳號、伺服器或資料庫。儲存成功後，重新整理或再次開啟同一網站，仍可讀取原有任務。同一網站的其他分頁若修改儲存資料，頁面會同步更新。

### 資料限制

- 資料只屬於目前裝置、瀏覽器與網站來源。
- 不會同步至 GitHub 或其他裝置。
- 本機 HTML 與 GitHub Pages 網站的資料不會自動互通。
- 清除網站資料後，紀錄可能永久遺失。
- 本版本未提供匯出、匯入或備份功能。

### 錯誤處理

- 無法讀取儲存資料時，顯示提示。
- 儲存空間不足或瀏覽器禁止儲存時，顯示失敗訊息。
- 儲存失敗時，不將操作顯示為成功。
- 沒有任務或沒有符合篩選條件的任務時，顯示明確提示。

## 十五、技術與部署規劃

| 技術 | 用途 |
| --- | --- |
| HTML | 建立頁面結構、表單、導覽與視窗 |
| CSS | 實作配色、卡片、日曆、矩陣與響應式版面 |
| JavaScript | 處理任務操作、搜尋、篩選、排序與統計 |
| LocalStorage | 保存本機任務資料 |
| GitHub Pages | 公開靜態網頁 |

所有 HTML、CSS 與 JavaScript 整合在單一 `index.html`，不需建置工具或外部套件。

GitHub 儲存庫的根目錄放置：

```text
taskflow/
├── index.html
└── README.md
```

`index.html` 為可操作的網頁，`README.md` 為本規格書。GitHub Pages 使用 `main` 分支的根目錄作為發布來源。

## 十七、AI 協作與修改紀錄

本專案透過需求討論與 AI 協作逐步完成：

1. 整理製作動機、使用者與功能需求。
2. 依規格產生單一 HTML 初版。
3. 將配色調整為奶油白背景與暖橘重點色。
4. 將側邊導覽改為頂部導覽，調整卡片與手機版面。
5. 新增可切換月份與選取日期的日曆。
6. 將搜尋與篩選移到工作區最上方。
7. 將任務統計移到左側。
8. 檢查程式語法，以及日曆的日期、跨年、閏年與篩選邏輯。

瀏覽器實際操作與部署後驗收，仍需依第十六節逐項確認。

## 十八、預期成果

TaskFlow 將任務記錄、狀態管理與時間規劃整合在同一工作台。使用者可透過列表掌握任務內容，透過日曆與時間軸查看截止安排，再利用優先矩陣比較重要性與時間壓力。

本專案呈現從需求規格、AI 協作實作、介面修改、功能檢查到 GitHub Pages 部署的製作流程，並保留後續擴充與改善的基礎。
